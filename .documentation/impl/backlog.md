Internal:

- Library edge case (ngx-formidable, not fixed): if a user clears the autocomplete and leaves it within 200 ms, the old value stays in the model behind an empty input. That's because the deselect only runs while the field is focused. Normal typing speed is fine.
- **Suffix Outside The Panel Toggle**:
  - **Context**: EnerQi added `cmp-ui-field-clear`, a `formidableFieldSuffix` button on every `horizontal` field (input, textarea, date, time, dropdown, autocomplete), built after the **Clear** example under **Actions** in [`user/decoration.md`](../user/decoration.md): rendered by `@if` while the field holds a value, `(click)` writes the empty value through the forms API. On a dropdown or date field the button lands right of the chevron, and when it vanishes after the click the chevron jumps right by the button's width. Visible in EnerQi's branch `feature/form-field-suffixes`, story `View Modules / Patients / Customer Edit Form / Edit Existing Customer`, Gender and Date of Birth.
  - **Defect**: `field-suffix-horizontal` pins the suffix wrapper at `right: 0`, and the toggle mixin in `_forms.scss` pushes the dropdown and date toggle inward by `field-padding-right()`, the measured suffix inset. So a suffix always sits outside the toggle, and a suffix whose width changes moves the toggle. MUI, PrimeNG, Fluent and Chrome's date input anchor the toggle at the edge and render a clear control inside it; Ant Design swaps the chevron for the clear icon on hover; only Angular Material with a `matSuffix` clear ends up like this, and that is a known wart.
  - **Proposal**: the toggle keeps `margin-right: calc(border + field-padding-x())`, the suffix wrapper moves to `right: field-toggle-inset()`, and `field-value-inset('right')` stays as it is, since it already adds the suffix inset and the toggle inset. The wrapper's own right padding then becomes the gap to the toggle. Update the **Layouts** sketch and **Actions** in [`user/decoration.md`](../user/decoration.md) and the Specimen. EnerQi reserves the button's width meanwhile so nothing jumps.
- **Autocomplete Text Survives An External Clear**:
  - **Context**: the same EnerQi clear button, first built with `(mousedown)="$event.preventDefault()"` as **Actions** recommends, on the Country autocomplete of `cmp-address-fields`, bound with `[formField]`. Pick Switzerland, click the button: the model is `null`, the address rules drop the field's `aria-required`, but the input still reads "Switzerland". EnerQi dropped the `preventDefault` as a workaround, so the button takes focus and the field is blurred when the value is written; `cmp-ui-search`'s previous raw button worked for the same reason.
  - **Defect**: the `afterRenderEffect` in `AutocompleteField` syncs the input text to the value only while the field is unfocused, because `null` with text is also what typing a filter looks like. An external write while the field has focus is therefore ignored, and the old label stands over a `null` model.
  - **Proposal**: the effect tells its own `deselectOption()` from an external write, for example by remembering the value it last set itself, and syncs the text for every external write, focused or not. Related to the 200 ms edge case above.
- **Autocomplete Filter Remembers Its Last Text**:
  - **Context**: found by EnerQi's Playwright journey `customer.spec.ts` on the same Country field: `pressSequentially('Switzerland')`, pick the option, clear it with the button, `pressSequentially('Switzerland')` again. No panel opens and no option renders, so the journey times out; typing `Switz` instead works, which is the workaround the spec carries. A user typing the same word again without a pause longer than 200 ms hits it too.
  - **Defect**: `registerAutocomplete()` runs `filterChangeSubject$` through `debounceTime(200)` and `distinctUntilChanged()`, and the external-write sync calls `setFilterText('')` without touching the subject. The debounced value is still the previous text, so the identical text is swallowed before the panel opens and the options update; `filterChange` still emits from `onInput`, so the consumer's fuzzy filter sees the text while the field shows nothing.
  - **Proposal**: the sync also resets the subject with `filterChangeSubject$.next(text)`, or the pipe drops `distinctUntilChanged()`.

- **Autocomplete Arrow**: add an arrow to autocomplete field to open panel and show all options; or allow dropdown to enter text? (e.g. Country field); also open panel with keyboard shortcut like datefield
- **Panel Resize**: allow the panel to be resized to show more/less options; it's probably best to keep the size "stored" per field in a form and not generalize it

- **Typeahead UX**: type-ahead feels unnatural and intransparent, improve UX
- **AI Support**: help developers use this library through AI. Open question: an MCP server, or other ways.
- **Date Range Field**: the largest item here. Split it before starting.
  - **The Calendar Is Not The Problem**: Pikaday renders ranges, with `startRange` / `endRange` options and `is-inrange` / `is-startrange` / `is-endrange` classes. What it does not do is manage range _selection_; that is driven from `onSelect`, or with two instances.
  - **The Value Contract Is**: `date-field` is single-valued end to end: `Date | null`, one picker, one masked input with one `unicodeTokenFormat`, arrow-stepping over that one date, and `isFilled`. A range mode means a tuple value, a two-segment mask, parse and format path, per-segment arrow-stepping and clear semantics, and range styling that `_pikaday.scss` does not have.
