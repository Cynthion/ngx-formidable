# Backlog

## Bugs

External:

- **Directive Validators On A Custom Control**: `@angular/forms` binds a `FormValueControl` under `ngModel`, `[formControl]` and `formControlName` through `setupCustomControl()`, which never calls `setUpValidators()`, so a directive validator such as `required` or `minlength` beside the field is never attached to its control. Upstream, reported on [angular/angular#69756](https://github.com/angular/angular/issues/69756); `forms-api-state.spec.ts` fails once it is fixed. Then drop the `DIRECTIVE_VALIDATORS_UNATTACHED` skips, and the **Template-Driven Forms Validate No Field** compromise in [`tech/forms-integration.md`](../tech/forms-integration.md), [`user/forms.md`](../user/forms.md) and [`user/validation.md`](../user/validation.md).
- **Parse Errors One Check Late**: under `ngModel` and `[formControl]`, `@angular/forms` takes a `transformedValue` parse error into the control from an effect that runs after the host's template and calls `updateValueAndValidity({ emitEvent: false })`, which marks nothing for check, so the field's `errors` input follows only on the host's next check. `BaseDateTimeField` works around it with one `markForCheck()` after render. Upstream, reported as [angular/angular#71127](https://github.com/angular/angular/issues/71127); `forms-api-state.spec.ts` fails once it is fixed. Then drop the workaround, which the `unparseable text` specs in `date-time-field.spec.ts` then pass without, and its exception in [`impl/components.md`](components.md).
- **Angular ESLint On `valueOf`**: `@angular-eslint/eslint-plugin`'s `reactive-context-must-read-signal` looks a bare call's name up on a plain object, so `({ valueOf }) => valueOf(path.pickup)`, the idiom Angular's documentation uses in a logic function, finds `Object.prototype.valueOf` and crashes the whole lint run with `config.args is not iterable`. The Studio's exported schema calls `context.valueOf()` instead. Fixed upstream in [angular-eslint/angular-eslint#3198](https://github.com/angular-eslint/angular-eslint/issues/3198), so far in prereleases only. No spec notices the release: once Renovate brings a stable release with the fix, return the export to the idiom in `schema-serializer.ts`, its spec and the golden exports.
- **Standard Schema Path Through A Missing Key**: `validateStandardSchema` throws a `TypeError` for an issue whose path runs through a key the model lacks, where an unknown last key falls back to the path the schema validates. The portal's `rulesOn` keeps a rule off the form unless every field it reads is there. Upstream, reported as [angular/angular#71128](https://github.com/angular/angular/issues/71128); `vest-integration.spec.ts` fails once it is fixed. Then change the statements that such an issue throws in [`user/validation.md`](../user/validation.md), [`tech/portal.md`](../tech/portal.md) and [`tech/forms-integration.md`](../tech/forms-integration.md) to the fallback.

Library:

- **Parse Against Today**: `parseUnicodeDateTime` takes the parts a format leaves out from today. On the day a daylight-saving switch skips an hour, a time field rejects a time in that hour as a `parse` error: `02:30` in Europe/Zurich on 2026-03-29. CI runs in UTC, which has no switch, so only a local run on that day sees it. A date format naming the day but not its month or year, such as `dd.MM`, rejects a day today's month or year lacks: 29 February in a common year. `format.helpers.spec.ts` pins today so its properties stay deterministic. Parsing against a fixed reference date would remove both.
- **Case Of Typed Names**: a typed month name or meridiem must match date-fns' own case. `15 dec 2024` against `dd MMM yyyy` and `02:30 pm` against `hh:mm a` report a `parse` error, though the mask accepts lowercase letters.
- **Meridiem Before A Dot**: date-fns reads a dot right after the meridiem as part of it, `AM.` as `a.m.`, so a time format such as `hh a.mm` never parses what it shows. `validateUnicodeTokenFormat` accepts it; `format.helpers.spec.ts` leaves that shape out of the formats it generates.
- **Highlight On A Disabled Option**: when the list changes and the highlighted option has turned disabled or readonly, the highlight stays on it, though the arrows skip such options and a highlight clamped onto one is moved off. `Enter` picks nothing there. The ARIA patterns allow a disabled option to take the highlight, so decide which rule the option fields follow.
- **Backspace Over A Whole Masked Text**: with the whole text of a masked field selected, as keyboard focus selects a full value, `Backspace` empties the editor but leaves the model as it was. ngx-mask clears that selection itself on `keydown` and reports it only to its own value accessor, with no `input` event, and the fields listen for `input`. `Delete` takes the browser's path and empties both. The portal's Phone Number shows it: `Tab` in, `Backspace`, and the model drawer still holds the number and calls the form valid. Seen on `input-field` and `date-field`. The `BACKSPACE_UNREPORTED` skips in `focus-caret-keys.spec.ts` and `date-time-field.spec.ts` pass once it is fixed.
- **Mask State Behind A Written Value**: a masked field puts a value the form writes into its editor itself, past ngx-mask, which goes on taking the field for empty until the user types. In a field holding such a value, `Ctrl`/`Cmd` + `A` selects nothing, and a click inside the selection keyboard focus made keeps that selection instead of placing the caret: the field reads the selection on `mouseup`, before the browser collapses it, and writes it back after ngx-mask's `click` has clamped it to the length it believes. Seen on the portal's Phone Number, Date and Time. The `MASK_STATE_BEHIND` skips in `focus-caret.spec.ts` and `focus-caret-keys.spec.ts` pass once it is fixed.
- **A Step Still In Flight**: `stepSegment` steps the text in the editor, and its commit renders the new text from a timer. An arrow pressed before that timer runs steps the old text again, so two presses arriving in one task step once. Human key repeat is slower than the timer; automated input is not. The `STEP_IN_FLIGHT` skip in `date-time-field.spec.ts` passes once it is fixed.
- **Mask Length Trims Its Alternatives**: `analyzeMaskDisplayLength` trims a mask and each of its `||` alternatives, which ngx-mask does not, so a mask opening or closing on a space counts short and the `minlength` and `maxlength` checks against it can misfire. `mask.helpers.spec.ts` leaves that shape out of the masks it generates.
- **Tab Out Of An Open Calendar**: with the date field's calendar open, `Tab` leaves focus on the page instead of moving on. The field closes its panel on the `keydown`, but the panel hides only once change detection runs, after the browser has moved focus to the calendar's Previous Month button, which then hides and drops it. The portal's Date shows it. A dropdown or autocomplete panel holds nothing focusable, so `Tab` moves on there. The `TAB_INTO_CLOSING_CALENDAR` skip in `panel.spec.ts` passes once it is fixed.
- **Display Label Selected On Tab**: `Tab` into a dropdown holding a value selects its label, painted in the selection colour, as Chrome does for any input it tabs into. Yet the dropdown keeps `Cmd`/`Ctrl` + `A` from the browser so that no highlight appears on a label it draws, which `display-only-selection.spec.ts` pins after a click focus. The portal's Pizza shows it. **The Caret On Focus** in [`user/fields.md`](../user/fields.md) says a keyboard entry selects the content, so decide whether that covers a display-only label, then drop either the selection or the select-all guard.
- **Unreachable Focus Guard**: `AutocompleteField.setFilterText` emits `filterChange` only while the field is not focused, but its one caller, the render effect, already returns while the field is focused, so the guard never decides anything. Delete it, or the effect's own check, and keep the comment that explains the rule beside the one that stays.
- **Masked Model Keeps Its Literals**: `BaseTextField.value` is documented as the text unmasked, and `dropSpecialCharacters` defaults to `true`, yet typing `0791234567` into `000 000 00 00` writes `079 123 45 67`: `editorValue` re-applies the mask through `NgxMaskPipe` rather than removing it. A value written without the literals shows the same text. The portal's phone rule and `caret.spec.ts` rely on the spaces, so decide which is the contract.
- **Readonly Slider Takes No Click**: a click on a readonly slider leaves it unfocused, though **What Every Field Shares** in [`user/fields.md`](../user/fields.md) says a click still focuses a readonly field. Its `.is-readonly` rule in `styles/mixins/_forms.scss` sets `pointer-events: none` on the range, so no press reaches it, and `preventPointerDown`, which keeps the press from moving the thumb and focuses the field instead, never runs. A readonly field also leaves the tab order, so only `focus()` reaches this one. Deleting that `pointer-events: none` fixes it, and the slider specs in `blocked-edits.spec.ts` still pass without it. The `READONLY_SLIDER_UNCLICKABLE` skip in `focus.spec.ts` passes once it is fixed.
- **Value-Top Adornment Above The First Line**: a textarea's prefix and suffix sit one field border above its first line. `field-prefix-suffix-value-top` in `styles/mixins/_forms.scss` offsets them by the textarea's top padding from the field's outer edge and leaves the border out: one pixel in the default theme, six under a `6px` `--formidable-field-border-thickness`. The `VALUE_TOP_ABOVE_FIRST_LINE` skip in `field-decorator.spec.ts` passes once it is fixed.

Portal:

The field editor offers the slider both, and the adornment examples apply to it, yet nothing shows. **Capabilities Are Declared, Not Assumed** in [`tech/portal.md`](../tech/portal.md) rules that out; declaring it `VERTICAL` fixes it. The `SLIDER_DECLARED_INLINE` skip in `studio-settings.spec.ts` passes once it is fixed.
- **Panel Overflows At Its Narrowest**: dragged to `INSPECTOR_WIDTH_MIN` in the two-column layout, the editor panel paints past its gutter twice. The last of the form export's four file tabs is cut off, and under `Shape The Corners One At A Time` the corner labels overlap and the unit selects are clipped. The `NARROWEST_OVERFLOWS` skip in `inspector-layout.spec.ts` passes once it is fixed.
- **A Following Variable States Its Default**: a derived variable nobody pinned states the library's default, while the value in force is its base's. Under the starting preset `--formidable-border-radius` is `12px`, and the field radius, the panel radius and the four corners that follow it all paint `12px`, yet their controls on `Variables` state `0.5rem`. `ThemeStore.valueOf` falls back to `defaultOf`, which reads the library's block, not the theme on screen. The `FOLLOWER_STATES_DEFAULT` skip in `portal.spec.ts` passes once it is fixed.

## Features

- **Renovate & Dependabot**: document the distinction and what is what, both probably need to be set up. The goal is to bump dependencies that change and belong together in the same PRs. Less PRs are appreciated.
- **Import The Schema**: the Studio's template import leaves a field's readonly and disabled state, its limits, its required marker and its condition behind, because the export states them as rules in `my-form.form.ts`. Reading back the one grammar `schema-serializer.ts` writes, pasted beside the template, would round-trip the whole form again.
- **One Divider Style**: the resize divider's look is restated in `inspector.scss`, `model-drawer.scss` and `docs-page.scss`. One global rule on `.portal-resize-handle`, the class `ResizeHandle` puts on its host, would replace all three.
- **Focus Ring Colour**: the library has no variable for the focus ring's colour, so the `soft` geometry restates all three `--formidable-color-*-focus-box-shadow` composites to make the ring translucent. A ring colour derived from the border colour, which a scheme could override alone, would replace the three composites with one declaration.
- **Hidden State**: Signal Forms' `hidden()` reaches a field as the `FormUiControl` `hidden` input. The decorator could honour it and hide itself with its field, where today the consumer writes `@if (!form.address().hidden())`.
