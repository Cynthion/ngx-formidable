# Backlog

## Bugs

- **EnerQi**: Constitution form accepts the same constitution as primary and secondary. After picking primary, the matching secondary option is never `[disabled]` (see the `TODO fix the disabling effect` in `constitution-form.component.html`), so the click is accepted and the form ends invalid showing `…secondary.not-equals`. Happens with and without zone. Root cause is upstream: `ngx-formidable`'s `BaseOptionFieldDirective` re-combines its projected options only when the `contentChildren` query changes, never when a projected option's `option()` does, so a `[disabled]` or `[label]` changing in place stays stale in the field. Fix upstream, then remove the `option()` read in `cmp-ui-search`, which works around the same limitation. Reproduce in the `Forms / Constitution Form` story.
- **Date Panel Opening Is Misdocumented**: [`user/fields.md`](../user/fields.md) says the dropdown, autocomplete and date fields open "on click, on `ArrowDown`, or on typing". The date field opens only from its toggle or `Alt` + `ArrowDown`; a click on its input places the caret, and the same document states that a plain `ArrowDown` does not open it. Fix the sentence under Focus.

## Features

- **Required Marker Names Read As Their Opposite**: A marker renders only when the field's `showRequiredMarker` (default `false`) and the form's or app's `showRequiredMarkers` (default `true`) are both true. The two names differ by one letter but play opposite roles: the singular requests a marker, the plural can only veto one. `showRequiredMarkers` has no visible effect at its default, so `false` is its only meaningful value, and `provideNgxFormidable({ defaults: { showRequiredMarkers: true } })` reads as "markers on" while changing nothing — a consumer reading the defaults table expects markers and gets none. `showRequiredMarker` is also documented as presentational only, yet it sets `aria-required`, which declares the field required to assistive technology. Proposal: rename the field input to `markRequired` (the glyph and `aria-required`), and the form input and the `FormidableDefaults` key to `hideRequiredMarkers`, default `false` (the glyph only), so each name states what it does and each default is the value that does nothing. `required` stays out of both names, because Angular's `RequiredValidator` matches `[required][ngModel]`. Update [`user/decoration.md`](../user/decoration.md), [`user/validation.md`](../user/validation.md), [`user/components.md`](../user/components.md), [`user/getting-started.md`](../user/getting-started.md) and the Studio's App Defaults with it.
