# Backlog

## Bugs

External:

- **Directive Validators On A Custom Control**: `@angular/forms` binds a `FormValueControl` under `ngModel`, `[formControl]` and `formControlName` through `setupCustomControl()`, which never calls `setUpValidators()`, so a directive validator such as `required` or `minlength` beside the field is never attached to its control. Upstream, reported on [angular/angular#69756](https://github.com/angular/angular/issues/69756); `forms-api-state.spec.ts` fails once it is fixed. Then drop the `DIRECTIVE_VALIDATORS_UNATTACHED` skips, and the **Template-Driven Forms Validate No Field** compromise in [`tech/forms-integration.md`](../tech/forms-integration.md), [`user/forms.md`](../user/forms.md) and [`user/validation.md`](../user/validation.md).
- **Parse Errors One Check Late**: under `ngModel` and `[formControl]`, `@angular/forms` takes a `transformedValue` parse error into the control from an effect that runs after the host's template and calls `updateValueAndValidity({ emitEvent: false })`, which marks nothing for check, so the field's `errors` input follows only on the host's next check. `BaseDateTimeField` works around it with one `markForCheck()` after render. Upstream, reported as [angular/angular#71127](https://github.com/angular/angular/issues/71127); `forms-api-state.spec.ts` fails once it is fixed. Then drop the workaround, which the `unparseable text` specs in `date-time-field.spec.ts` then pass without, and its exception in [`impl/components.md`](components.md).
- **Angular ESLint On `valueOf`**: `@angular-eslint/eslint-plugin`'s `reactive-context-must-read-signal` looks a bare call's name up on a plain object, so `({ valueOf }) => valueOf(path.pickup)`, the idiom Angular's documentation uses in a logic function, finds `Object.prototype.valueOf` and crashes the whole lint run with `config.args is not iterable`. The Studio's exported schema calls `context.valueOf()` instead. Fixed upstream in [angular-eslint/angular-eslint#3198](https://github.com/angular-eslint/angular-eslint/issues/3198), so far in prereleases only. No spec notices the release: once Renovate brings a stable release with the fix, return the export to the idiom in `schema-serializer.ts`, its spec and the golden exports.
- **Standard Schema Path Through A Missing Key**: `validateStandardSchema` throws a `TypeError` for an issue whose path runs through a key the model lacks, where an unknown last key falls back to the path the schema validates. The portal's `rulesOn` keeps a rule off the form unless every field it reads is there. Upstream, reported as [angular/angular#71128](https://github.com/angular/angular/issues/71128); `vest-integration.spec.ts` fails once it is fixed. Then change the statements that such an issue throws in [`user/validation.md`](../user/validation.md), [`tech/portal.md`](../tech/portal.md) and [`tech/forms-integration.md`](../tech/forms-integration.md) to the fallback.
- **ngx-mask Loses A Bound Value**: with `showMaskTyped`, a change to `NgxMaskDirective`'s bound `value` model, `[value]` or `[(value)]` without a forms API, is lost. The binding fires `ngOnChanges`, whose `_applyMask()` re-renders the stale `_inputValue` before the `value` effect writes the new one, and reports that empty text back through `valueChange`, so the model is emptied and the field shows its slots. The masked fields write through `writeValue` and set the `value` model themselves instead, see **Writing Through The Mask** in [`tech/caret.md`](../tech/caret.md). Upstream, reported as [NepipenkoIgor/ngx-mask#1671](https://github.com/NepipenkoIgor/ngx-mask/issues/1671), with a fix that syncs `_inputValue` from a changed `value` in `ngOnChanges`. `value-round-trip.spec.ts` fails once it is fixed. Then `writeMaskedValue` may become a `[value]` binding.

## Features

- **Renovate & Dependabot**: document the distinction and what is what, both probably need to be set up. The goal is to bump dependencies that change and belong together in the same PRs. Less PRs are appreciated.
- **Import The Schema**: the Studio's template import leaves a field's readonly and disabled state, its limits, its required marker and its condition behind, because the export states them as rules in `my-form.form.ts`. Reading back the one grammar `schema-serializer.ts` writes, pasted beside the template, would round-trip the whole form again.
- **One Divider Style**: the resize divider's look is restated in `inspector.scss`, `model-drawer.scss` and `docs-page.scss`. One global rule on `.portal-resize-handle`, the class `ResizeHandle` puts on its host, would replace all three.
- **Focus Ring Colour**: the library has no variable for the focus ring's colour, so the `soft` geometry restates all three `--formidable-color-*-focus-box-shadow` composites to make the ring translucent. A ring colour derived from the border colour, which a scheme could override alone, would replace the three composites with one declaration.
- **Hidden State**: Signal Forms' `hidden()` reaches a field as the `FormUiControl` `hidden` input. The decorator could honour it and hide itself with its field, where today the consumer writes `@if (!form.address().hidden())`.
